# Appendix C -- Profile matrix (normative)

*Generated from `profiles/profile-matrix.json` by `tools/gen_profile_matrix.py`.
Do not edit this file; edit the JSON. `conformance/check_profiles.py` proves the
two agree, checks every cell against `schema/dsx.schema.json`, and checks the
reference files in `examples/` against their own row.*

Sections 1.3, 2.3, 3, 4.2.5, 7 and 10.9 each state profile applicability for the
members they introduce. This appendix is the single place where all of it is
collected, and it is normative: where a cell here and a sentence elsewhere
disagree, that is a defect, and `check_profiles.py` is where it surfaces.

**Reading the table.** `MUST` -- the member is required in a file declaring that
profile; its absence is REJECT (5.6). `MAY` -- optional, but a reader of that
profile MUST understand it when present. `MUST NOT` -- its presence is REJECT; a
file that needs the member declares a higher profile. `cond.` -- a condition in
the notes decides, not the profile alone.

Profiles are cumulative: no member goes from `MUST` at a lower profile to
`MUST NOT` at a higher one. The reverse -- `MUST` at L0 relaxing to `MAY` at L1
-- does occur, and `drones[].trajectory_sampled` is the case: L0 has no other
way to carry a trajectory, while above L0 the sampled track is a derived cache.

## Notes

<a id="c1"></a>**1. `dsx`**  
the format version. A file without it is not a DSX file.

<a id="c2"></a>**2. `profile`**  
the declared profile is what this whole matrix is indexed by; it can have no default.

<a id="c3"></a>**3. `show.duration_ms`**  
REQUIRED as a member, but null where the show is open-ended (R10.24). Null suspends the 1.4 guarantee (A25).

<a id="c4"></a>**4. `show.audio`**  
1.3 lists 'audio sync' under L2. What is L2-specific is synchronising flight to it (sync: gnss); carrying a track is not, and an L0 consumer that ignores audio still flies the correct show.

<a id="c5"></a>**5. `frame`**  
3: REQUIRED at every profile, including L0. Positions without a frame are not positions.

<a id="c6"></a>**6. `time.time_source`**  
OPTIONAL at L2 in v0.1, not REQUIRED: the holdover policy is specified but not yet mandated, and one of the two L2 reference files omits it. See A39.

<a id="c7"></a>**7. `fleet`**  
device-profile binding starts at L1 (1.3). At L0 there is no binding, so drones[].fleet is a free-text group label; from L1 it MUST resolve to a fleet entry -- checked, not assumed.

<a id="c8"></a>**8. `drones[].fleet`**  
label at L0, reference at L1 and above (see fleet).

<a id="c9"></a>**9. `drones[].trajectory`**  
*Condition:* REQUIRED unless the aircraft flies roles (10): a rotation file carries the choreography in roles[].trajectory and the airframe inherits it through an assignment.  
FORBIDDEN at L0 because the segment track is authoritative where both exist (4.1). An L0 reader cannot evaluate segments, so it would silently fly the derived cache while the file says something else.

<a id="c10"></a>**10. `drones[].trajectory_sampled`**  
the only trajectory form an L0 file may carry; above L0 it is a derived cache that a validator MUST check against 4.4.

<a id="c11"></a>**11. `drones[].light`**  
at L0 the referenced program MUST be limited to R, G and B: a channel an L0 consumer cannot represent does not belong in a file that declares L0.

<a id="c12"></a>**12. `drones[].payloads`**  
payloads and actuators are L2 (1.3). A reader below L2 has no arm/disarm state machine, and a payload it ignores is a payload nobody is holding.

<a id="c13"></a>**13. `drones[].sorties`**  
*Condition:* at most one sortie per airframe below L2 (10.9): one flight, one aircraft. Rotation is L2.  

<a id="c14"></a>**14. `takeoff`**  
1.3 lists the takeoff grid as an L1 ingredient, which is not the same as making it mandatory: a rotation file places aircraft through launch_stack instead, and both L2 reference files do exactly that.

<a id="c15"></a>**15. `roles`**  
FORBIDDEN at L0 for the same reason as drones[].trajectory: roles carry segment tracks.

<a id="c16"></a>**16. `open_ended`**  
an open-ended show is L2 only, and it still has to end (R10.24).

<a id="c17"></a>**17. `energy`**  
*Condition:* REQUIRED where the file declares rotation (waves with two or more entries, or wave_cycle): a rotation plan without an energy budget is a wish.  

<a id="c18"></a>**18. `safety`**  
7.1: at L0 the object is optional because an L0 file makes no safety claim at all.

<a id="c19"></a>**19. `safety.min_separation_m`**  
REQUIRED whenever safety is present -- it is what the object exists to state.

<a id="c20"></a>**20. `safety.geofence`**  
the operative, onboard-evaluable fence is termination.geofence (7.3); this one is the show-level envelope and is not duplicated as a requirement.

<a id="c21"></a>**21. `termination.escalation`**  
REQUIRED whenever termination is present: the four rungs and the one-step rule are the object's purpose.

<a id="c22"></a>**22. `termination.fallback_channel`**  
the independent second channel is an L2 construct (7.2); below L2 there is no termination policy for it to serve.

<a id="c23"></a>**23. `termination.disarmed_fall_containment`**  
7.5: REQUIRED at L2, and checkable -- the safety area MUST contain the fall trajectory of a disarmed aircraft from any show position. The fall model itself is still open (A30).

<a id="c24"></a>**24. `position_integrity`**  
1.3 advertises the GNSS integrity policy as an L2 ingredient. v0.1 does NOT make it REQUIRED, and neither L2 reference file carries it. Stating that here is the point of this appendix; whether it becomes REQUIRED at L2 in v0.2 is A39.

<a id="c25"></a>**25. `interference_policy`**  
as position_integrity: specified, not yet mandated (A39).

<a id="c26"></a>**26. `extensions_required`**  
an unknown entry here is REJECT at every profile (5.6) -- must-understand does not weaken as the profile drops.

<a id="c27"></a>**27. `extensions`**  
any object may carry one; unknown members outside it are an error, not an extension.

<a id="c28"></a>**28. `provenance.content_hash`**  
2.3: OPTIONAL at L0/L1, REQUIRED at L2.

<a id="c29"></a>**29. `segments.start_yaw_deg`**  
yaw is L2 (1.3, 4.2.5). All-or-nothing per track, and never part of the canonical reduction of 4.4.5.

<a id="c30"></a>**30. `segments.segments[].yaw_deg`**  
present exactly when start_yaw_deg is present.


## Profiles in one line each

**L0 Sampled** -- positions and RGB, sampled. The floor of the format: every
conformant file reduces to it (1.4), and an L0 consumer needs no interpolation,
no device model and no safety machinery.

**L1 Show** -- adds segment trajectories, light programs, device-profile binding
and the show-level safety envelope. This is the profile a designer works in.

**L2 Production** -- adds yaw, payloads, rotation and multi-wave operations,
termination policy, provenance and signatures. This is the profile an operator
files with an authority.
