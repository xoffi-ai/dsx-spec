## Problem

What goes wrong today? Be concrete: a show that could not be exchanged, a
conversion that lost data, a field that had to be guessed, an incident.
Field experience is evidence here.

## Proposal

The change itself. Include the JSON as it would appear in a file.

## Why this shape

Why this design and not the obvious alternatives. If another format or industry
already solved this, say which and how.

## Safety impact

Does this change what happens when something fails? If yes: what failure does
it prevent, and **how would a validator check it**? A safety-relevant field
that cannot be checked automatically is only half a proposal.

## Compatibility

- Does it break existing files? (If yes, it is a major version — see GOVERNANCE §5.)
- Is it an optional addition, an extension, or a regulatory profile?
- What must an existing reader do if it does not understand it?

## Open questions

What you are unsure about. Listing them is not a weakness; a proposal with an
honest open-questions section gets accepted faster than one that hides them.
